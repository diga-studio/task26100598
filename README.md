# itemcf

由上层调用的 ItemCF 推荐库。评分快照与计算结果均保存在进程内存中，
只处理固定快照，不做增量更新、并发调用或故障恢复。

## API

```go
// 从完整评分快照构建推荐数据，refDay 为参考日 T。
rec := itemcf.Build(ratings, refDay)

// 为快照中的用户生成推荐，blacklist 中的商品被排除出候选。
recs := rec.Recommend(userID, blacklist)
```

- `Rating{UserID, ItemID, Score, Day}`：整数用户ID、整数商品ID、1..5 评分、整数评分日。
- `Recommendation{ItemID, Score, Top, Other}`：按得分降序、商品ID升序的前 20 件；
  `Top` 为绝对贡献最大的至多 3 个历史商品及其带符号贡献（绝对值相同按商品ID升序），
  `Other` 为其余贡献之和，`Top` 贡献之和加 `Other` 精确等于 `Score`。

## 计算定义

- 记录权重 = (评分 - 用户均分) × 2^(-(T-评分日)/30)，用户均分为其全部评分的算术平均。
- 商品相似度 = 全部用户坐标上的权重余弦；分母用各商品的全部评分，任一模长为 0 则为 0。
- 候选 = 快照全部商品 − 用户评过的商品（含权重为 0）− 黑名单。
- 候选得分 = Σ(历史权重 × 相似度) ÷ (历史权重绝对值之和 × ln(2+候选评分人数))；
  绝对值之和为 0 时所有候选得分为 0。零分候选（含无共同评分用户的商品）排在负分候选之前。

## 实现要点

- 构建：用户/商品双向索引（用户→评分、商品→评分者）、商品模长及其倒数、按商品ID升序表。
- 推荐第一遍按评分者聚合：先算 s_v = Σ(历史权重 × 归一化权重)，再向 v 的全部商品累加，
  避免按“用户对”展开，长尾用户/热门商品不退化。
- 第二遍仅对最终前 20 名计算贡献解释；暂存空间跨查询复用（故不支持并发查询）。

## 测试

```sh
go test -v -timeout 20m .
```

- `itemcf_test.go`：小数据与独立按定义计算的参考实现逐条比对（误差 ≤ 1e-9，排序一致）；
  覆盖热门正分商品被屏蔽后零分候选仍排在负分候选之前、用户均分消去全部权重等边界。
- `scale_test.go`：确定性规模测试（100000 用户 / 100000 商品 / 2000000 评分，
  含 10 名各 20000 条评分的用户与 1 件 50000 人评分的热门商品）；
  断言构建 + 100 个不同用户完整推荐（含贡献解释）的合计 CPU 时间 ≤ 60s、峰值堆内存 ≤ 512 MiB，
  并核对抽取用户（含长历史用户）的完整候选排名与贡献解释。
